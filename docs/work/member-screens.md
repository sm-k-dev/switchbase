# 회원 화면·문구 (member, 2단계)

작성: 디자이너 / 2026-11-08 / 기준: `docs/work/member-design.md` §5, §7

## 1. 산출물

| 파일 | 내용 |
|---|---|
| `templates/member/login.html` | 로그인 화면 (`/login`) |
| `templates/member/signup.html` | 가입 화면 (`/signup`) |
| `templates/member/signup-done.html` | 인증 메일 발송 안내 (`POST /signup` 성공, `POST /signup/resend` 공용) |
| `templates/member/verify-result.html` | 인증 결과 (`GET /verify`) |
| `static/css/main.css` | `.auth`, `.auth-form`, `.alert`(-error/-warn/-info), `.field-hint`, `.resend-box`, `.button` 추가 |
| `templates/fragments/layout.html` | 헤더 닉네임 표기를 `sec:authentication="principal.nickname"`로 변경 |

## 2. 화면 흐름

```
[로그인] ──성공──> /switches
   │ 실패(비밀번호 불일치) → /login?error
   │ 실패(미인증)          → /login?unverified  (인증 메일 재발송 폼 표시)
   │ 로그아웃 후          → /login?logout
   └─ 회원가입 링크
[가입] ──검증 실패──> 같은 화면에 필드별 오류 (입력값 유지, 비밀번호 제외)
   └─성공──> [인증 메일 발송 안내] ──메일 링크──> [인증 결과]
                                             ├ 성공 → 로그인 버튼
                                             └ 실패 → 재발송 폼 → [인증 메일 발송 안내]
```

## 3. 모델 계약 (개발자가 맞출 것)

| 템플릿 | 속성 | 규칙 |
|---|---|---|
| `login.html` | 쿼리 `error` / `unverified` / `logout` | 존재 여부만 본다(`param.x != null`). 값은 쓰지 않음 |
| `signup.html` | `signupForm` (`email`, `nickname`, `password`, `passwordConfirm`) | 필드 오류는 `th:errors`로 표시. **password·passwordConfirm은 값을 다시 채우지 않는다** (템플릿에서 `th:field`를 쓰지 않음) |
| `signup-done.html` | `email` (선택) | `POST /signup` 성공 시에는 `email`을 넣는다. **재발송(`/signup/resend`)에서는 넣지 않는다** — 계정 존재 여부를 드러내지 않기 위해 같은 안내 문구를 쓴다 |
| `verify-result.html` | `success` (boolean) | 실패 시 재발송 폼이 자동 표시된다 |

- 모든 폼은 `th:action` 사용 → CSRF 토큰 자동 삽입. 직접 `<input name="_csrf">`를 넣지 않는다.
- 재발송 폼의 필드 이름은 `email`.

## 4. 문구 (한국어, 운영용 — 개발 힌트 문구 없음)

### 4.1 화면 제목·버튼

| 위치 | 문구 |
|---|---|
| 로그인 제목 / 버튼 | 로그인 / 로그인 |
| 로그인 하단 | 아직 회원이 아니신가요? 회원가입 |
| 가입 제목 / 버튼 | 회원가입 / 가입하기 |
| 가입 하단 | 이미 회원이신가요? 로그인 |
| 인증 메일 발송 제목 | 인증 메일을 보냈어요 |
| 인증 성공 제목 / 버튼 | 이메일 인증이 완료되었어요 / 로그인하러 가기 |
| 인증 실패 제목 | 인증 링크를 확인할 수 없어요 |
| 재발송 제목 / 버튼 | 인증 메일을 다시 받기 / 인증 메일 다시 받기 |

### 4.2 필드 라벨·힌트

| 필드 | 라벨 | 힌트 |
|---|---|---|
| 이메일 | 이메일 | 가입 후 이 주소로 인증 메일을 보내드려요. |
| 닉네임 | 닉네임 | 2~20자. 화면에 보이는 이름이에요. |
| 비밀번호 | 비밀번호 | 8자 이상이어야 해요. 한글은 약 24자, 영문·숫자는 72자까지 가능합니다. |
| 비밀번호 확인 | 비밀번호 확인 | (없음) |
| 재발송 이메일 | 가입한 이메일 | (없음) |

### 4.3 안내·성공 메시지

| 상황 | 문구 |
|---|---|
| 로그아웃 후 | 로그아웃되었습니다. |
| 가입 완료 (signup-done) | `{email}`으로 인증 메일을 보냈습니다. 메일함(스팸함 포함)에서 링크를 눌러 인증을 완료해 주세요. |
| 가입 완료 — 재발송 공용 (email 없음) | 인증 메일을 보냈습니다. 메일함(스팸함 포함)에서 링크를 눌러 인증을 완료해 주세요. |
| 가입 안내 하단 | 링크는 24시간 동안 유효하며 한 번만 사용할 수 있어요. |
| 인증 성공 | 이제 가입한 이메일과 비밀번호로 로그인할 수 있어요. |
| 인증 실패 | 링크가 올바르지 않거나 만료되었어요. 인증 링크는 24시간 동안 유효하며 한 번만 사용할 수 있습니다. |

### 4.4 오류 메시지 (`member-design.md` §5 규칙 기준)

`messages.properties` 또는 어노테이션 `message`에 그대로 넣는다. 키 이름은 개발자가 정해도 된다.

| 대상 | 조건 | 문구 |
|---|---|---|
| email | 빈 값·형식 오류 | 올바른 이메일 주소를 입력해 주세요. |
| email | 255자 초과 | 이메일은 255자 이하로 입력해 주세요. |
| email | 이미 가입됨 | 이미 사용 중인 이메일입니다. |
| nickname | 2~20자 위반 | 닉네임은 2~20자로 입력해 주세요. |
| nickname | 빈 값 | 닉네임을 입력해 주세요. |
| nickname | 중복 | 이미 사용 중인 닉네임입니다. |
| password | 8자 미만 (글자 수 기준) | 비밀번호는 8자 이상이어야 해요. |
| password | UTF-8 72바이트 초과 (한글은 글자당 3바이트) | 비밀번호가 너무 길어요. 한글은 약 24자, 영문·숫자는 72자까지 가능합니다. |
| password | 빈 값 | 비밀번호를 입력해 주세요. |
| passwordConfirm | 불일치 | 비밀번호가 서로 다릅니다. |
| passwordConfirm | 빈 값 | 비밀번호를 한 번 더 입력해 주세요. |
| 전역 | 가입 처리 중 알 수 없는 오류 | 가입을 처리하지 못했어요. 잠시 후 다시 시도해 주세요. |
| 로그인 | 아이디·비밀번호 불일치 | 이메일 또는 비밀번호가 올바르지 않습니다. |
| 로그인 | 미인증 (`/login?unverified`) | 이메일 인증이 완료되지 않았습니다. 가입 시 받은 인증 메일의 링크를 눌러 주세요. |

비고: 로그인 실패 문구는 "이메일 또는 비밀번호가 올바르지 않습니다" 하나로 통일했다. 미인증 여부는 비밀번호가 맞을 때만 `unverified`로 분기되므로(§5 참고) 문구에서 계정 존재를 따로 드러내지 않는다.

## 5. 개발자에게 전달할 확인 사항

1. **재발송 폼을 로그인 화면에도 둠**: 미인증 로그인 실패 시 `/login?unverified`에서 바로 재발송할 수 있게 `login.html`에 같은 폼을 넣었다. `member-design.md` §7에는 없던 화면 요소이므로 아키텍트 확인 필요. 빼도 흐름은 깨지지 않는다.
2. **`signup-done.html`의 `email`**: 재발송 응답에는 `email`을 넘기지 않는다(템플릿이 null이면 주소 줄을 생략함).
3. **비밀번호 값 미유지**: 검증 실패 시 비밀번호 입력칸은 비워진다. 의도된 동작.
4. **`param` 존재 검사**: 템플릿은 `${param.error != null}` 형태만 쓴다. 컨트롤러에서 별도 모델 속성이 필요 없다.
5. **헤더 닉네임**: `principal.nickname`이 동작하려면 인증 주체가 `MemberUserDetails`에 `getNickname()`을 가져야 한다(§3 설계와 일치).
6. **htmx**: 이번 화면은 모두 일반 폼 POST/redirect로 동작한다. htmx 부분 갱신은 사용하지 않았다(필요해지면 아키텍트 결정).

## 6. 반응형

- 폭 400px 기준 단일 열 카드. 480px 이하에서 여백 축소, 헤더 줄바꿈 허용.
- 입력칸·버튼은 `font: inherit`, 최소 높이는 기본 패딩(약 36px)으로 터치 가능.
- 가로 스크롤 없음 (본문 `max-width: 960px`, 좌우 16px 여백은 기존 `body` 규칙 유지).

## 7. 접근성

- 각 입력칸은 라벨로 감싸 연결됨. 힌트·오류는 라벨 안에 있다.
- 오류 필드에 `aria-invalid="true"` 설정(테두리 빨강).
- 알림 영역은 `role="alert"`(오류) / `role="status"`(안내).
- 로그인 `autofocus`는 이메일 칸, 가입 `autofocus`는 이메일 칸.
