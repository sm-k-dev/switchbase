# 3단계 설계: 타건음 샘플, A vs B 비교, 입문자 가이드, 빌드 조건 필터

작성: 아키텍트 / 2026-11-20 / 상태: **확정** (2026-11-20, 사용자 결정 Q1~Q8 추천안 적용. §9 참고)
기준: `docs/HANDOFF.md` §3(타건음은 유튜브 임베드 + 시작 시간, 비교 단위는 "같은 채널", 빌드 조건 필터, 감각 용어 사전), §4 3단계

## 1. 목표와 범위

포함
- 회원이 스위치 1종의 타건음 샘플을 **유튜브 링크 + 시작 시간 + 녹음 조건**으로 등록한다. 파일은 올리지 않는다(저작권).
- 스위치 상세에서 샘플을 재생하고, 같은 채널 샘플을 우선 보인다.
- A vs B 비교 화면: 스펙, 체감 평균 레이더, 같은 채널 샘플 나란히 보기.
- 입문자 가이드와 감각 용어 사전.
- 빌드 조건 필터로 체감 평균을 좁혀 본다(예: 하우징 재질, 윤활 여부).

제외
- 녹음 조건 **자동 제안**(LLM). 4단계 ⑥.
- 유튜브 채널·영상 메타데이터 자동 조회. 외부 API 키가 필요하므로 이번 범위에서는 제외(§9 Q2).
- 샘플 파일 업로드, 자체 호스팅 오디오.

## 2. 핵심 원칙

- **저작권**: 음원 파일을 저장하거나 재배포하지 않는다. 유튜브 영상을 임베드하고 시작 시간만 저장한다.
- **같은 조건끼리 비교**: 타건음은 녹음 환경에 따라 달라진다. 비교 화면은 **같은 채널** 샘플을 우선하고, 다른 채널끼리 비교하면 "녹음 조건이 다름"을 표시한다.
- **사람이 판단**: 샘플 등록과 숨김·삭제는 사람이 버튼으로 한다. AI는 이번 단계에서 쓰지 않는다.
- **표본 수**: 체감 평균 옆에는 항상 평가 수(N명·M건)를 보인다. 3단계의 필터 결과도 같다.
- **이메일 비공개**: 어떤 화면에도 이메일을 쓰지 않는다. 등록자는 닉네임만 보인다.

## 3. 데이터: `V11__create_sound_sample.sql` (V1~V10 수정 금지)

```sql
-- 타건음 샘플. 파일이 아니라 유튜브 영상 id와 시작 시간만 저장한다(저작권).
CREATE TABLE sound_sample (
    id              BIGSERIAL     PRIMARY KEY,
    switch_id       BIGINT        NOT NULL REFERENCES keyboard_switch (id),
    member_id       BIGINT        REFERENCES member (id) ON DELETE SET NULL,
    youtube_id      VARCHAR(11)   NOT NULL,                 -- 영상 id(11자)
    start_seconds   INT           NOT NULL DEFAULT 0,       -- 시작 시간(초)
    channel_name    VARCHAR(100)  NOT NULL,                 -- 채널 이름(사람이 입력)
    hidden          BOOLEAN       NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMPTZ   NOT NULL DEFAULT now(),
    deleted_at      TIMESTAMPTZ,
    CONSTRAINT ck_sound_start CHECK (start_seconds >= 0),
    CONSTRAINT ck_sound_youtube_id CHECK (youtube_id ~ '^[A-Za-z0-9_-]{11}$')
);
-- 같은 스위치에 같은 영상·시작 시간은 한 번만 (삭제 제외)
CREATE UNIQUE INDEX uk_sound_sample_active
    ON sound_sample (switch_id, youtube_id, start_seconds) WHERE deleted_at IS NULL;
CREATE INDEX ix_sound_sample_switch_channel ON sound_sample (switch_id, channel_name);

-- 녹음 조건 태그 (고정 선택지, 코드값은 애플리케이션 enum과 맞춘다)
CREATE TABLE sound_sample_condition (
    sound_sample_id  BIGINT       NOT NULL REFERENCES sound_sample (id) ON DELETE CASCADE,
    condition_code   VARCHAR(30)  NOT NULL,
    PRIMARY KEY (sound_sample_id, condition_code)
);
```

- `member_id`는 탈퇴 시 `ON DELETE SET NULL`로 연결만 끊는다. 샘플은 "탈퇴한 회원" 이름으로 남는다(§9 Q5에서 정책 확인).
- 녹음 조건 코드는 `CASE_OPEN`(케이스 없음), `CASE_CLOSED`(케이스 있음), `KEYBOARD_ON_DESK`(책상 위 본체), `PHONE_MIC`(휴대폰 녹음), `PRO_MIC`(전문 마이크), `NOT_SURE`(모름) 같은 고정 목록으로 시작한다. 목록은 §9 Q3에서 확정한다.
- 행 수가 늘어도 열은 그대로다. 빌드·채널·조건은 열이 아니라 행으로 표현한다.

## 4. 권한과 규칙

| 동작 | 권한 |
|---|---|
| 샘플 보기 | 누구나(로그인 없이) |
| 샘플 등록 | 로그인 회원 |
| 샘플 수정 | 등록자만 |
| 샘플 삭제 | 등록자 또는 관리자 |
| 샘플 숨김 | 관리자(신고 처리 흐름) |
| 숨김 샘플 | 등록자에게만 보이고 해제는 등록자만(후기·평가와 같은 규칙) |

- 같은 스위치·같은 영상·같은 시작 시간은 한 번만 등록한다(부분 유니크). 중복 등록은 "이미 있는 샘플이에요"로 안내하고 기존 샘플로 이동한다.
- 유튜브 주소는 다음 형식만 받는다: `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`. 그 밖의 주소와 시작 시간이 음수이거나 영상 길이를 넘는 경우는 등록하지 않는다. 영상 길이 확인은 API 없이 할 수 없으므로 제외한다(§9 Q2).

## 5. 화면과 동작

### 5.1 샘플 등록

- 경로: `GET /switches/{id}/sounds/new`, `POST /switches/{id}/sounds`
- 입력: 유튜브 주소(또는 영상 id), 시작 시간(`mm:ss` 또는 초), 채널 이름, 녹음 조건(여러 개)
- 시작 시간은 `1:23`과 `83`을 모두 받고 저장은 초 단위로 한다.
- 등록 뒤 스위치 상세의 샘플 목록으로 돌아간다.

### 5.2 스위치 상세의 샘플 목록

- 경로: 기존 `GET /switches/{id}` 하단에 `sounds/section.html` 조각을 붙인다.
- 같은 채널 샘플을 위에 두고, 채널별로 묶는다. 샘플마다 유튜브 임베드(`youtube-nocookie.com`)와 시작 시간을 넣는다.
- 임베드는 클릭 전까지 로드하지 않는다(썸네일을 누르면 임베드). 외부 요청을 사용자가 누를 때만 보내기 위해서다.
- 영상이 삭제되었거나 비공개면 재생이 안 될 수 있다. 샘플마다 "재생이 안 되면 신고해 주세요" 안내와 신고 링크(기존 신고 흐름)를 둔다.

### 5.3 A vs B 비교

- 경로: `GET /switches/compare?a={id}&b={id}`. 기존 `/switches/{id}/compare`(버전 비교)와 충돌하지 않도록 경로를 나눈다.
- 구성:
  1. 스펙 표: 제조사, 타입, 압력, 거리, 재질 등. 다른 값은 강조한다(기존 `CompareRow` 재사용).
  2. 체감 레이더: 소리 크기, 소리 성향 비율, 타건감 비율, 피로도. 표본 수를 옆에 적는다.
  3. 샘플: 두 스위치의 **같은 채널** 샘플을 나란히 둔다. 같은 채널이 없으면 "같은 채널 샘플이 없어요"를 보이고, 각자 대표 샘플을 따로 보여 준다.
- 두 스위치가 같거나 없는 스위치면 404 또는 안내 후 목록으로 돌려보낸다.
- 비교 결과는 저장하지 않는다. 주소로 공유할 수 있다.

### 5.4 빌드 조건 필터

- 스위치 상세와 비교 화면의 체감 요약에 필터를 둔다: 하우징 재질, 보강판, 마운트, 윤활 여부(§9 Q4에서 항목 확정).
- 필터는 평가가 연결된 빌드(`rating.build_id`)를 기준으로 좁힌다. 빌드 없이 한 평가는 "빌드 조건 미지정"으로 따로 센다.
- 결과 옆에 필터를 적용한 표본 수를 항상 보인다. 표본 수가 기준 미만이면 평균을 숨긴다(§9 Q6 기준값).
- 집계는 **실시간 조회**한다(기존 요약과 같은 방식). 캐시는 필터 조합이 많아 이번 단계에서는 만들지 않는다.

### 5.5 입문자 가이드와 감각 용어 사전

- 경로: `GET /guide` (입문자 가이드), `GET /guide/terms` (용어 사전). 평가 화면에서는 항목 옆 링크로 연결한다.
- 용어 사전 내용은 DB가 아니라 템플릿 파일로 둔다(v1). 내용을 바꾸려면 개발자가 고치고 배포한다. 관리자 편집 화면은 나중에 검토한다(§9 Q7).
- 용어 항목은 `소리 성향`(도각·쪅·묵직·둔탁), `타건감`(부드러움·명확함·걸림), `피로도`처럼 평가 항목과 같은 이름을 쓴다. 정의는 사람이 쓴다.

## 6. 집계 규칙

- 체감 평균은 기존과 같이 평가 건 기준이다. 표본 수는 회원 수와 건수를 같이 쓴다.
- 샘플 자체는 평균에 들어가지 않는다(샘플은 소리 자료, 평가는 체감 의견).
- 숨김 평가와 탈퇴 30일 경과 평가는 기존 집계 제외 조건을 그대로 쓴다(`RatingStatsService`와 같은 세 조건).

## 7. 확정 사항과 확인 요청

확정(HANDOFF §3에서 가져옴)
- 타건음은 파일을 올리지 않고 유튜브 임베드 + 시작 시간으로만 단다.
- 비교 단위는 같은 채널이다.
- 빌드 조건으로 평균을 좁힌다.
- 표본 수를 평균 옆에 항상 보인다.

이번 문서에서 제안한 것(사람 확인 필요는 §9)
- 샘플 등록과 숨김·삭제 권한(§4).
- 임베드는 클릭 뒤 로드(§5.2).
- 필터는 실시간 조회, 캐시는 나중(§5.4).
- 용어 사전은 템플릿 파일(§5.5).

## 9. 사용자 결정 (2026-11-20, 추천안 적용)

- **Q1. 샘플 등록 기준** → **결정: 로그인 회원 누구나.** 평가 없이도 샘플만 올릴 수 있다.
- **Q2. 유튜브 메타데이터** → **결정: 직접 입력.** API 키와 할당량 문제를 피한다.
- **Q3. 녹음 조건 목록** → **결정: §3의 목록 그대로.**
- **Q4. 필터 항목** → **결정: 하우징과 윤활 2개로 시작.**
- **Q5. 탈퇴 회원의 샘플** → **결정: 후기와 같은 규칙(탈퇴 30일 뒤 삭제).**
- **Q6. 최소 표본 수** → **결정: 평가 3명 미만이면 필터 결과 평균을 숨긴다.**
- **Q7. 용어 사전 관리** → **결정: 템플릿 파일로 시작.** 관리자 편집 화면은 나중에 검토.
- **Q8. 재생 실패 대응** → **결정: 신고로만 처리.** 자동 감지는 API가 필요하므로 하지 않는다.

## 10. 테스트 목록 (개발자, 제안)

- 유튜브 주소 형식별 파싱(정상·잘못된 형식·음수 시간·형식 외 주소)
- 같은 스위치·영상·시작 시간 중복 등록 거부
- 등록자만 수정, 등록자 또는 관리자만 삭제, 타인은 403
- 숨김 샘플은 등록자에게만 보이고 해제는 등록자만
- 비교 화면: 같은 채널 우선, 같은 채널이 없을 때 안내, 같은 스위치 비교 거부
- 필터: 빌드 있는 평가만 좁힘, 빌드 없는 평가는 "미지정"으로 집계, 표본 수 기준 미만 평균 숨김
- 탈퇴 회원 샘플 표시와 집계 제외 조건 일치
- 임베드는 클릭 전까지 외부 요청이 없음(화면 테스트)

## 11. 열린 위험

- **저작권·영상 삭제**: 유튜브 영상이 삭제되거나 비공개로 바뀌면 재생이 안 된다. 신고 경로로만 정리한다.
- **채널 이름 신뢰도**: 사람이 입력하므로 틀릴 수 있다. 같은 채널 비교의 정확도가 떨어진다.
- **외부 요청**: 임베드는 유튜브 서버로 요청을 보낸다. 클릭 뒤 로드로 줄이지만 개인정보 처리방침(외부 제공)에 한 줄 추가가 필요하다.
- **샘플 품질**: 녹음 조건이 제각각이라 평균처럼 한 줄로 비교하기 어렵다. 조건 표시를 항상 함께 보인다.
