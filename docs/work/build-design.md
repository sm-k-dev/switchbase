# 빌드 등록 설계 (2단계)

작성: 아키텍트 / 2026-11-08 / 상태: **확정** (2026-11-08, 사용자 답변 Q1~Q8 반영)
기준: `docs/HANDOFF.md` §3 "빌드 환경은 스위치가 아니라 평가 한 건에 붙는다", §3 데이터 모델 `build`, §4 2단계 "빌드 등록, 체감 평가 + 개조 태그"

## 1. 목표와 범위

포함
- 로그인 회원이 자기 키보드 빌드를 등록한다.
- 빌드를 수정하고 숨김 처리한다(숨김 해제 포함).
- 공개 목록과 상세 화면.
- 핵심 항목(고정 선택지)과 자유 메모.

제외 (별도 항목)
- 체감 평가(`rating`)와 평가에 빌드 연결(`build_id`) → "체감 평가 + 개조 태그" 항목. 윤활(`윤활 여부`)도 평가 쪽에 둔다.
- 개조 태그 자동완성(`mod_tag`, `rating_mod_tag`).
- 빌드 조건 필터 → 3단계.
- 사진 업로드(HANDOFF에 없음).

## 2. 핵심 원칙

- 빌드는 스위치가 아니라 **사용자 키보드 1대**다. 회원에게 붙는다.
- 빌드 없이도 평가할 수 있어야 한다(평가 항목에서 다룬다).
- 핵심 항목은 **고정 선택지**(집계·필터용). 나머지 개조는 자유 태그(다음 항목).
- 편집자·작성자 표시는 **닉네임만**. 이메일은 어떤 화면에도 나오지 않는다(0단계 규칙).

## 3. 데이터: `V6__create_build.sql` (V1~V5 수정 금지)

```sql
CREATE TABLE keyboard_build (
    id               BIGSERIAL    PRIMARY KEY,
    member_id        BIGINT       NOT NULL REFERENCES member (id) ON DELETE CASCADE,
    name             VARCHAR(50),                        -- 선택. 비우면 화면에 "내 키보드"로 표시 (Q7)
    housing_material VARCHAR(30),                        -- 고정 선택지 코드, NULL = 미지정
    plate_material   VARCHAR(30),                        -- 보강판 고정 선택지 코드, NULL = 미지정
    mount_type       VARCHAR(30),                        -- 마운트 고정 선택지 코드, NULL = 미지정
    keycap_material  VARCHAR(30),                        -- 키캡 고정 선택지 코드, NULL = 미지정
    memo             VARCHAR(500),                       -- 자유 텍스트 (Q7). "기타" 설명도 여기에 적는다 (Q6)
    hidden           BOOLEAN      NOT NULL DEFAULT FALSE, -- 숨김. 데이터는 유지 (Q4)
    version          BIGINT       NOT NULL DEFAULT 0,    -- 낙관적 잠금
    created_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX ix_keyboard_build_member ON keyboard_build (member_id);
CREATE INDEX ix_keyboard_build_visible ON keyboard_build (hidden, created_at DESC);
```

- 고정 선택지 값은 **코드 값**(영문 대문자)으로 저장하고, 화면 표시 이름은 코드와 분리해 둔다(예: `PC` → "폴리카보네이트(PC)").
- 윤활은 이 테이블에 없다(Q5: 평가 쪽).
- `build_id`는 이번 항목에서 만들지 않는다(평가 항목에서 추가).
- 이름 `name`은 NULL 허용. 저장은 빈 값을 NULL로 정규화한다.

### 고정 선택지 (Q5-2 초안 그대로 확정)

| 항목 | 코드 | 표시 이름 |
|---|---|---|
| 하우징 | `ABS` | 플라스틱(ABS) |
| | `PC` | 폴리카보네이트(PC) |
| | `ALUMINUM` | 알루미늄 |
| | `BRASS` | 황동 |
| | `OTHER` | 기타 |
| 보강판 | `NONE` | 없음 |
| | `PC` | 폴리카보네이트(PC) |
| | `FR4` | FR4 |
| | `ALUMINUM` | 알루미늄 |
| | `OTHER` | 기타 (Q6: 허용) |
| 마운트 | `TOP` | 탑(Top) |
| | `GASKET` | 가스켓(Gasket) |
| | `TRAY` | 트레이(Tray) |
| | `PLATE` | 플레이트(Plate) |
| | `PCB` | PCB 마운트 |
| | `OTHER` | 기타 (Q6: 허용) |
| 키캡 | `ABS` | ABS |
| | `PBT` | PBT |
| | `OTHER` | 기타 |

- 모든 항목에 **미지정**(NULL)을 기본으로 둔다.
- 하우징·키캡의 `OTHER`(기타)는 Q5-2 초안에 있던 항목이라 그대로 둔다. Q6 답변은 마운트·보강판의 기타 허용만 명시한다.

## 4. 권한과 규칙

| 행동 | 누가 | 조건 |
|---|---|---|
| 목록·상세 보기 | **비로그인 포함 누구나** (Q2 공개) | 숨김 빌드는 목록·상세에서 빠짐 (작성자 본인 제외, 아래 참고) |
| 등록 | **로그인 회원** | 회원당 **20개** 제한 (숨김 포함, Q3) |
| 수정 | **로그인 회원 누구나** (Q1) | 낙관적 잠금 `version` |
| 숨김·숨김 해제 | **로그인 회원 누구나** (Q1, Q4) | 숨김 해제 버튼도 같은 권한 |

- **비로그인 여부**: 보기는 비로그인 가능, 등록·수정·숨김·해제는 로그인 필수. 비로그인 POST는 로그인 화면으로 보낸다.
- 숨김 빌드는 목록에서 빠지고, 상세는 **작성자 본인에게만** 보인다. 다른 회원에게는 404.
- 권한은 서비스에서 검사한다(화면 숨김에 기대지 않음, 위키와 같은 원칙).
- 회원당 20개 제한은 숨김 빌드도 개수에 넣는다(숨김으로 한도를 우회하지 못하게 함).
- 편집자 표시는 닉네임만. 이메일 비노출.

### 권한 확장에 따른 위험 (확정 사항의 결과)
- Q1 결정으로 로그인 회원 누구나 **다른 사람의 빌드도 수정·숨김**할 수 있다. 위키의 "즉시 공개 + 관리자 되돌리기" 방식과 달리 빌드에는 이력이 없어(Q8) 원래 값을 되돌릴 수 없다. 이 위험은 확정을 바꾸지 않되 리뷰어가 확인하고, 필요하면 "작성자 본인만"으로 다시 좁히는 항목을 따로 둔다.
- 이를 줄이기 위해 **숨김 해제**가 반드시 있어야 한다(숨김은 되돌릴 수 있어야 함). 설계에 포함한다.

## 5. 화면

| 화면 | 경로 | 템플릿 | 로그인 | 비고 |
|---|---|---|---|---|
| 목록 | GET `/builds?page=` | `builds/list` | 불필요 | 숨김 제외, 20건, 이름(없으면 "내 키보드")·작성자 닉네임·핵심 항목 요약 |
| 상세 | GET `/builds/{id}` | `builds/detail` | 불필요 | 핵심 항목·메모. 숨김이면 작성자 외 404. 수정·숨김 버튼은 로그인 회원에게 |
| 등록 폼 | GET `/builds/new` | `builds/form` | 필요 | 회원당 20개 초과 시 거부 문구 |
| 등록 저장 | POST `/builds` | (실패 시 `builds/form`) | 필요 | 성공 → 상세 |
| 수정 폼 | GET `/builds/{id}/edit` | `builds/form` | 필요 | |
| 수정 저장 | POST `/builds/{id}` | (실패 시 `builds/form`) | 필요 | 충돌 → 409 재렌더 |
| 숨김 | POST `/builds/{id}/hide` | — | 필요 | 성공 → 상세(숨김 상태 표시) 또는 목록 |
| 숨김 해제 | POST `/builds/{id}/unhide` | — | 필요 | 성공 → 상세 |

- 고정 선택지는 `<select>`, 기본값 "미지정".
- 메모는 자유 텍스트 500자, 이름은 선택 입력 50자.
- 숨김 확인은 문구로 한 번 묻는다(디자이너).

## 6. 확정된 정책 (사용자 답변)

| # | 확정 |
|---|---|
| Q1 | 수정·숨김은 **로그인 회원 누구나**. 관리자 여부와 무관. (비로그인 여부는 §4에 명시) |
| Q2 | **공개**. 목록·상세에 작성자 닉네임 표시, 이메일 제외 |
| Q3 | 회원당 **20개** |
| Q4 | **숨김**(`hidden=true`, 데이터 유지). 하드 삭제 없음. 숨김 해제 가능 |
| Q5 | 윤활은 **평가 쪽**. 빌드 테이블에 없음 |
| Q5-2 | 하우징·보강판·마운트·키캡 고정 선택지는 §3 초안 그대로 |
| Q6 | 마운트·보강판에 **"기타" 허용**(설명은 메모). 하우징·키캡의 "기타"는 Q5-2 초안에 따라 포함 |
| Q7 | 이름 **선택**, 비우면 "내 키보드"로 표시. 메모 **500자 자유 텍스트** |
| Q8 | 수정 이력 **남기지 않음** |

## 7. 작업 분담

1. **개발자**
   - V6, `KeyboardBuild` 엔티티(`ddl-auto: validate` 통과), 리포지토리.
   - 서비스: 등록(회원당 20개 검사, 이름 빈 값 → NULL), 수정(낙관적 잠금), 숨김·숨김 해제(상태 토글), 고정 선택지 코드 검증(범위 밖 값 거부), 상세 접근 검사(숨김이면 작성자 외 404).
   - 컨트롤러와 `SecurityConfig` 규칙: `/builds`, `/builds/{id}` GET은 permitAll, 나머지 쓰기 경로는 `authenticated()`.
   - 표시 이름 매핑은 코드 값과 분리(enum 또는 상수).
   - 테스트 §8.
2. **디자이너**
   - `builds/list`, `builds/detail`, `builds/form`(고정 선택지 `<select>`, 미지정 기본, 이름 빈 값 "내 키보드" 표시, 메모 500자).
   - 숨김·숨김 해제 버튼과 확인 문구. 숨김 상태는 작성자에게만 표시.
   - 닉네임만 표시. 이메일 없음.
3. **리뷰어**: 쓰기 경로의 서버 권한(로그인 여부), 숨김이 목록·상세(작성자 외)에 새지 않는지, 회원당 20개 우회 여부, 낙관적 잠금, 이메일 비노출, §4 위험 항목.
4. **테스트 실행**: 개발자 한 명만 `sg docker -c "./gradlew test"`.

## 8. 테스트 목록 (개발자)

- 로그인 회원 등록 → 목록·상세에 보임, 작성자 닉네임 표시, 이메일 없음.
- 이름 비움 → 저장은 NULL, 화면은 "내 키보드".
- 비로그인 등록·수정·숨김 → 로그인 화면으로.
- 회원당 20개 초과 등록 → 거부(숨김 빌드 포함해서 세는지 확인).
- 다른 회원이 수정 → 성공(Q1), 수정 이력 없음 확인.
- 다른 회원이 숨김 → 목록에서 빠짐, 숨김 해제 → 다시 보임.
- 숨김 빌드 상세: 작성자 200, 다른 회원·비로그인 404.
- 수정 충돌(옛 version) → 409 재렌더.
- 고정 선택지 범위 밖 값 → 거부(서버 검증). "기타"는 허용.
- 목록 20건 페이징, 숨김 제외.
- 응답 본문에 이메일 없음(목록·상세·폼 재렌더).

## 9. 열린 위험

- Q1 확정에 따라 다른 회원의 빌드를 수정·숨김할 수 있다. 이력이 없어(Q8) 원래 값 복구는 수동이다. 리뷰에서 확인하고 필요하면 권한을 좁힌다.
- 고정 선택지 코드를 바꾸면 기존 데이터와 어긋난다. 코드와 표시 이름을 분리했으므로 바꿀 때는 마이그레이션을 만든다.
- 평가 항목에서 `build_id`를 연결할 때 숨김 빌드를 평가에서 어떻게 다룰지 다시 정한다.
