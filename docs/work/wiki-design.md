## 1. 목표와 범위

포함
- 로그인한 회원이 스위치 스펙을 수정한다. 수정은 **즉시 게시**된다(검토 대기 없음, 사용자 결정).
- 수정마다 `switch_revision`에 스냅샷을 남긴다(기존 구조 재사용).
- 두 리비전의 스펙 차이를 보는 **버전 비교** 화면.
- **되돌리기**(수정 취소): 최신 수정을 직전 스냅샷으로 되돌리는 새 리비전을 만든다. 관리자 또는 그 수정을 한 본인만 가능(사용자 결정).
- 전체 스위치의 **최근 변경 목록**.

제외(4단계 이후)
- AI "의심" 표시, 검토 대기 흐름(revision 상태 `검토 대기`), 되돌림 상태 값.
- 과거 임의 시점으로의 복원(관리자 전용 기능 포함, §6 Q2에서 범위 확인).
- 별칭·출처의 이력(§6 Q3에서 확인).
- 신고, 편집 횟수 제한(§6 Q5).

## 3. 데이터: `V5__wiki_revision_editor.sql` (V1~V4 수정 금지)

```sql
-- 편집자를 회원 행과 연결한다. 권한 판단(되돌리기 본인 확인)은 이 값으로 한다.
ALTER TABLE switch_revision
    ADD COLUMN editor_member_id BIGINT REFERENCES member (id) ON DELETE SET NULL;

-- 최근 변경 목록을 시간순으로 읽는다.
CREATE INDEX ix_switch_revision_created ON switch_revision (created_at DESC);
```

- `editor` 컬럼은 **닉네임 스냅샷**으로 쓴다(새 행부터). 닉네임 길이는 최대 20자라 `VARCHAR(50)`에 들어간다.
- 기존 행: `editor_member_id`는 NULL. 화면에는 `editor`(관리자 이메일)를 **절대 쓰지 않고**, 기존 행은 "초기 관리자"로 표시한다. 기존 데이터는 고치지 않는다(§6 Q4).
- 수정 권한 판단은 `editor_member_id`로 한다. 닉네임은 권한 판단에 쓰지 않는다(중복 가능성 없음이지만 값이 바뀔 수 있는 표시 값이므로).

## 4. 권한과 규칙

| 행동 | 누가 | 조건 |
|---|---|---|
| 상세·이력·비교·최근 변경 보기 | 누구나(로그인 없이) | 기존 정책 유지 |
| 스위치 수정 | 로그인 회원(USER·ADMIN) | 이메일 인증 완료 회원만 로그인 가능하므로 별도 조건 없음 |
| 스위치 등록 | ADMIN | 기존 `/admin/switches/new` 유지(§6 Q1) |
| 수정 취소(되돌리기) | 관리자 **또는** 그 리비전의 작성자 | **그 리비전이 현재 최신일 때만** 가능(§6 Q2) |

공통 규칙
- 수정·취소는 즉시 게시. 리비전 `revision_no`는 `max + 1`.
- 낙관적 잠금: 폼에 `version`을 담아 보내고 불일치면 기존 충돌 문구 표시("그 사이 다른 사람이 먼저 고쳤어요…").
- 편집 요약은 필수(기존과 같음). 취소의 요약은 자동으로 `#N 수정 취소`로 채운다(사용자가 덧붙일 수 있음).
- 처음 등록(리비전 1)은 취소할 수 없다(직전 스냅샷이 없음).
- 취소는 **새 리비전을 추가**한다. 과거 리비전은 지우거나 고치지 않는다(이력 보존).

## 5. 동작과 화면

### 5.1 수정 (회원)
- 경로: `GET /switches/{id}/edit`, `POST /switches/{id}` (로그인 필요). 기존 `/admin/switches/{id}/edit`은 제거하고 회원 경로로 옮긴다.
- 폼은 기존 `admin/switch-form.html`을 공용 화면으로 옮긴다(디자이너). 안내 문구: "수정하면 바로 공개됩니다."
- 저장 → `SwitchService.update(...)`. 편집자는 `(memberId, nickname)`으로 기록한다.
- 별칭은 기존처럼 통째로 갈아 끼운다(§6 Q3에서 바뀔 수 있음).

### 5.2 이력·비교
- `GET /switches/{id}/history`: 리비전 목록(번호, 시각, 닉네임, 요약). 두 개를 고르면 비교로 이동.
- `GET /switches/{id}/compare?from=N&to=M`: 스펙 필드별 표(제조사·브랜드·모델·변형·타입·수치·출시 연도·설명). 값이 다른 행을 강조. 설명은 전후를 나란히 보여준다(줄 단위 diff는 하지 않음).
- 기본 상세 화면(`/switches/{id}`)의 "수정 이력" 목록은 history 페이지로 이어지게 한다.

### 5.3 되돌리기(수정 취소)
- `GET /switches/{id}/revisions/{no}/revert`: 확인 화면. 되돌릴 내용(#N-1 → #N 차이)을 보여 준다. 권한이 없거나 최신이 아니면 버튼 대신 사유를 보여 준다.
- `POST /switches/{id}/revisions/{no}/revert` (CSRF, `version` 포함): 서버가 권한과 최신 여부를 **다시** 확인 → `#N-1` 스냅샷을 현재 스위치에 적용하는 새 리비전 기록.
- 되돌리기 후 상세로 이동, 메시지 "#N 수정을 취소했어요".

### 5.4 최근 변경 목록
- `GET /changes?page=`: 전체 스위치의 리비전을 최신순 20건씩. 항목: 스위치 이름(상세 링크), 리비전 번호, 시각, 닉네임, 요약.
- 공개 페이지(로그인 없이).
- 조회는 리비전과 스위치를 함께 가져온다(`JOIN FETCH`, N+1 방지).

### 5.5 서비스 메서드 (개발자)
- `update(id, expectedVersion, spec, aliases, summary, editorMemberId, editorNickname, sourceUrl)`: 기존 시그니처에서 `editor` 문자열을 두 값으로 나눈다.
- `revert(id, revisionNo, expectedVersion, memberId, isAdmin, editorNickname)`: 권한·최신·첫 리비전 검사 후 `update`와 같은 경로로 기록.
- `compare(id, from, to)`: 두 스냅샷을 필드 쌍의 목록으로 반환.
- `recentChanges(pageable)`: 리비전 페이지.

### 5.6 보안 설정 (개발자)
- `SecurityConfig`: `GET /switches/**`, `GET /changes`는 permitAll. `POST /switches/{id}`, `GET·POST …/edit`, `…/revert`는 `authenticated()`. `/admin/**`은 ADMIN 유지.
- 되돌리기의 권한 판단은 화면이 아니라 서비스에서 한다(화면 숨김만으로는 막지 않음).

## 8. 테스트 목록 (개발자)

- 로그인 회원이 수정 → 즉시 공개, `revision_no`가 1 증가, 편집자 닉네임과 `editor_member_id` 저장.
- 비로그인 POST 수정 → 로그인 화면으로.
- 낙관적 잠금: 오래된 `version`으로 수정 → 충돌 문구, 리비전 증가 없음.
- 취소: 작성자 본인 최신 리비전 → 성공, 직전 스펙 복원, 새 리비전 기록, 별칭 불변.
- 취소 거부: 다른 회원 → 403, 최신이 아닌 리비전 → 거부, 리비전 1 → 거부.
- 관리자 취소: 최신이면 성공(작성자가 아니어도).
- 비교: 바뀐 필드만 "변경"으로 표시, 설명은 전후 모두 표시.
- 최근 변경 목록: 최신순, 20건 페이징, 스위치 이름 포함.
- 이메일 비노출: 상세·이력·최근 변경 응답 본문에 로그인 이메일이 없음. 기존 행은 "초기 관리자"로 표시.

## 9. 열린 위험

- 즉시 게시라 기물 훼손이 바로 보인다. 관리자가 최근 변경에서 되돌리는 것으로 대응한다(Q5).
- 별칭·출처는 되돌려지지 않는다(Q3). 되돌림 후 별칭이 어긋날 수 있다.
- 동시 취소 두 건은 낙관적 잠금으로 한 건만 통과한다(리뷰에서 확인).
